# 组织树与目录下钻

组织树按已索引文件相对于 `FILE_ROOT` 的真实目录层级生成。目录名无需包含部门编号、年份或任何固定格式；零字节占位文件也可以参与索引和目录统计，但不能用于表格内容预览或 BI 分析。没有已索引文件的空目录不会出现在树上。

本机直接启动时使用 `fast_file_finder/.env` 的 `FILE_ROOT`；Docker 使用根目录 `.env` 的 `SHARE_HOST_PATH` 挂载数据，容器内 `FILE_ROOT` 仍为挂载点。启动命令中的同名环境变量优先于 `.env`。更换目录后需要重启服务，并在“索引与同步”刷新索引。

目录浏览、首页统计和文件清单统一限定在当前根目录的索引作用域。点击目录时显示该目录及所有子目录的文件；右侧子目录卡片可以继续逐层下钻，面包屑可以返回上层。目录名中的 `%`、`_` 按普通字符匹配，不会匹配相似名称的邻接目录。仅看今日有更新的分支时，节点的文件总数仍包含其完整子树。

`GET /api/catalog/resolve?path=...` 将目录定位链接解析为当前根目录的路径。兼容正反斜杠、配置目录的快捷方式，以及旧演示链接的 `/data/share` 前缀。五个内置旧演示目录别名会映射到当前模拟数据的明确目录名；只有在目标已有索引文件时，服务才迁移旧归档规则和未关闭任务的路径，保留已关闭任务的历史记录。

目录范围约束不等于逐用户权限。当前账号角色主要用于管理员操作和下载审批，尚未实现按部门授权目录及向子目录继承的 ACL；给目录改名不会建立这类权限。


## 账号目录权限（2026-11-04）

目录层级下钻与账号授权分别处理，不需要修改模拟数据名称。应用目录 ACL 默认开启，授权管理位于「人员权限 → 目录访问授权」，仅超级管理员可用。按成员或精确部门授予目录后，子目录继承；拒绝规则优先于任何允许。未授权账号默认无文件可见。授权深层目录只显示通向该目录的祖先节点，不显示兄弟目录文件。

此权限适用于 API 数据查询、统计、AI、分析、归档、预览和下载；撤销后新请求立即生效。超级管理员保留当前根目录全量访问。后台索引器和定时归档仍维护完整索引，不依赖某个员工的授权，也不会写入或重命名网盘源文件。原生 SMB/NAS 文件权限尚未接入；应用登录身份不会自动映射到操作系统共享盘账号。
