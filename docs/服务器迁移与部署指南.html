架构设计：为什么绝不直接查网盘？
理解核心工作机制，避免将网盘拖垮

传统搜索平台直接在共享网盘（SMB / NFS）上做递归检索，一旦多员工并发，网盘 I/O 瞬间占满甚至死机。 本项目采用 **“本地磁盘高性能缓存索引 + 共享盘绝对只读”** 架构：

💡
核心原则：
1. 员工检索：只查服务器本地的高性能 SSD 磁盘（SQLite FTS5 索引表），耗时 10~20ms，完全不消耗共享网盘的任何网络与磁盘 I/O；
2. 共享盘只读（:ro）：容器没有任何删除或修改原文件的写权限，绝对安全；
3. 增量巡检：后台定时器或管理员点击“增量同步”时，才在后台低优先级遍历网盘更新索引。

本地电脑终端 (Mac/Linux)

在服务器宿主机挂载真实共享网盘
告别模拟数据，对接企业真实内网云盘（以 172.11.111.11 Windows 共享为例）
⚠️
新手常踩的坑：千万不要在 Docker 容器内部去 mount 网盘！
正确的标准姿势是：由服务器宿主机 Linux 操作系统挂载网盘为本地文件夹，容器直接映射该本地文件夹。这样即使网盘短暂闪断，宿主机也会自动重连，容器不会异常退出。
服务器终端 
# 1. 创建服务器本地挂载点目录
sudo mkdir -p /mnt/share/enterprise_disk

# 2. 创建 CIFS/SMB 账号密码凭据文件 (防止密码明文暴露)
sudo bash -c 'cat < /etc/cifs-credentials
username=your_smb_user
password=your_smb_password
domain=your_domain_if_any
EOF'

# 保护凭据文件权限 (仅 root 可读)
sudo chmod 600 /etc/cifs-credentials

# 3. 配置开机自动挂载到 /etc/fstab (关键参数: ro 只读, uid=10001 与容器内安全账号一致)
sudo bash -c 'echo "//172.11.111.11/share /mnt/share/enterprise_disk cifs credentials=/etc/cifs-credentials,ro,uid=10001,gid=10001,iocharset=utf8,nofail 0 0" >> /etc/fstab'

# 4. 立即执行挂载并测试查看
sudo mount -a
ls -la /mnt/share/enterprise_disk

✓ 如果 ls /mnt/share/enterprise_disk 能看到公司的真实文件夹（如 12-推广ROI周报、2-阿里平台-分销 等），说明网盘挂载大功告成！

生产标配：Nginx 域名反向代理与 HTTPS
为内网员工提供友好的专属域名 (如 search.company.com)

在服务器上的 /etc/nginx/conf.d/file_finder.conf 配置反向代理：

/etc/nginx/conf.d/file_finder.conf 
server {
    listen 80;
    server_name search.company.com;

    client_max_body_size 50M;

    location / {
        proxy_pass http://127.0.0.1:8080;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        
        # 针对 AI 流式长连接 (SSE) 优化
        proxy_buffering off;
        proxy_cache off;
        proxy_read_timeout 300s;
    }
}

重新加载 Nginx 配置即可生效：

服务器终端 
sudo nginx -t && sudo nginx -s reload

新手常见问题自救清单 (FAQ)
遇到意外报错不用慌，对照检查解决

Q1: 启动后在浏览器打开显示“拒绝访问”或无法连接？

A: 1) 检查服务器安全组与防火墙：执行 sudo ufw allow 8080/tcp 放行端口；
2) 检查 .env 中的 APP_BIND_ADDR 是否设置为了 0.0.0.0（如果是直接访问）或 127.0.0.1（如果通过本地 Nginx 反代）。

Q2: 挂载 Windows 共享网盘提示“Permission denied”？

A: 挂载命令必须包含 uid=10001,gid=10001。因为 Docker 容器是以无特权安全账号 appuser (uid 10001) 运行的，若未指定 uid，容器将无法读取挂载目录。

Q3: 公司网盘突然断线或重启，系统会卡死吗？

A: 绝对不会！因为所有检索均只读本地 SQLite，员工依然可以秒级搜表。我们在 /etc/fstab 配置了 nofail，宿主机会在后台自动重连网盘。

Q4: 怎样重启或更新服务？

A: 在项目目录下执行以下极简命令：
• 重启服务：docker compose restart app
• 停止服务：docker compose down
• 更新代码后重新构建：docker compose up -d --build
