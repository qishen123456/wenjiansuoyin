# 企业文件资产中心：升级方案 v2

更新：2026-11-04。根据 Claude 草案与当前代码、真实模拟目录核对后修订。

## 判断与范围

方向可行：先让用户找到可信文件，再完善治理和自动化。原草案按约 103 人周、多人团队估算，是产品方向，不能视为本项目已经验证的交付排期。按可运行的增量交付推进，每批以接口、页面和回归测试共同验收。现有 BI 保留维护，近期不扩展制表功能。

已有事实：当前目录有 130,452 份表格索引、25 个一级目录、5,934 个组织树节点，最深 15 层。129,895 份是零字节占位文件，因此可验证检索与目录结构，不能据此验收预览、系列准确率或真实报表新鲜度。

已经完成的工作不再重复排期：统一左侧导航、首页搜索与资产概览、结果预览、目录子节点卡片、真实根目录定位、当前根目录隔离、目录特殊字符匹配，以及五条旧归档规则的路径迁移。

## 对草案的关键修订

1. **空状态应真实可解释。** 不以假数据保证“默认有内容”；默认显示全部文件，确实无数据时给出操作入口。
2. **修改时间不是创建或入库时间。** 当前 `today_added` 实际使用 `mtime`，界面统一称“今日更新”。不能拿文件复制时间或首次扫描时间伪装业务报表期次。
3. **当前达标率不是按时归档率。** 当前达标率依据有效规则的非空文件与更新窗口计算。历史按时归档率必须先有每期应交时间、实际交付时间、豁免记录，当前不展示这个历史指标。
4. **无命中和无有效内容是治理异常。** 目录匹配不到文件、只有零字节文件、目录超出配置范围，应提示检查规则/数据，不自动当成某个团队逾期，也不能用它们自动关闭任务。
5. **目录范围不是用户 ACL。** 不按部门名称相似度猜权限。目录授权需要明确用户/组、目录 ID、继承与拒绝规则；搜索、统计、AI 候选、预览、导出和原文件接口必须使用同一过滤层。没有授权来源时不能宣称已实现部门隔离。
6. **预览限行必须在服务端完成。** 当前 SheetJS 预览会获取工作簿原始字节；在浏览器只显示前 N 行不能防止原件泄露，不能当作脱敏预览的验收证据。
7. **覆盖率须说明可观察范围。** 一次目录扫描的已发现文件可以对账为“成功处理 + 明确排除 + 文件元数据读取失败”；被排除/无权遍历的目录，其内部文件总数未知，不能声称统计了整个网盘。索引元数据失败与表格内容解析失败分别计数。
8. **零结果不能泄露受限文件存在。** 只有已获权限的范围才可诊断未入库等原因；隐藏权限模式不得泄露文件名、目录名、摘要或数量。权限过滤必须在召回和聚合前执行，AI 之前执行。
9. **埋点默认不存原始查询词、路径或单元格。** 收集事件、随机会话 ID、角色、数量、耗时与关联搜索 ID；管理员查看聚合基线。后续词汇运营另行配置访问范围、脱敏与保留期。
10. **自动关闭不能只依赖最新 mtime。** 第一批先排除空文件与错误规则。后续用规则周期、交付文件证据、文件版本和检查结果建立幂等闭环；回滚通过追加审计事件实现，不覆盖历史。
11. **不设置凭空的达标阈值和日期。** 30 秒、95%、98%、p95 30 分钟作为待验证目标；先记录真实基线。大促冻结及春节产能由实际团队确认。

## 第一批：可信地基（本次实施）

| 工作 | 实现与验收 |
| --- | --- |
| 指标字典 | 明确每个指标的来源、公式、时间字段、根目录范围；同一业务域的概览与目录清单对账 |
| 页面速修 | 删除身份切换入口；权限来自登录会话；树中移除“今日 0”；保留全名；统一“AI 助手、已关闭、归档检测、今日更新”等术语 |
| 服务端角色校验 | 规则变更、归档审核和账号管理要求管理员；不再返回明文密码，也不在浏览器持久保存密码；提交者、审核者由服务器会话写入；拒绝非法状态迁移，前端隐藏按钮不能代替后端校验 |
| 规则预检 | 保存前显示规范路径、匹配数量、非空文件数量、最近有效更新时间；零命中/无负责人不能启用；只有空文件时明确提示，不能据此自动关闭 |
| 扫描对账 | 记录扫描运行历史、已发现、成功处理、排除分类、文件异常、目录异常；失败不清理旧索引；同步页显示可观察范围与不完整状态 |
| 使用基线 | 搜索、结果选择、预览、复制、下载申请/审批、归档提交/审核、刷新触发事件；管理员显示零结果率、服务端搜索耗时分位数、有关联证据的有效操作占比 |
| 回归 | 目录隔离、特殊字符、无命中规则、空文件、审核越权、伪造操作者、扫描对账、埋点关联与隐私测试；浏览器验证主流程 |

“有效操作搜索占比”定义为：有合法关联搜索 ID、同一会话且搜索后 10 分钟内发生预览/复制/下载申请的搜索数 ÷ 搜索数。它是产品行为代理指标，不直接命名为“用户真正找到正确报表的比例”。没有数据时显示“待采集”。

## 第二批：权限与预览的统一边界

- 明确账号/组和目录授权来源；优先试点 09、12、23 三个域，不推断任何现有账号的业务访问权。
- 先实现应用目录 ACL，再根据实际 NAS/SMB 能力接原生文件权限。统计、召回、联想、历史、收藏、系列、缓存、AI 和下载均经过同一权限层。
- 实现服务端限行预览及权限相关的缓存键；限制原文件字节端点。按已确认的字段策略脱敏，并记录预览行为。
- 凭证治理：密码哈希、会话与共享令牌边界测试。与 ACL 一起作为生产推广前置门禁。
- 出口：跨目录、跨用户、过期授权、缓存命中、AI 候选等越权用例全部拒绝；原文件下载审批保持有效。

## 第三批：报表系列与搜索整合

- 系列先作为候选建议，不自动隐藏历史结果；同目录、文件名中的业务主题、期次与平台共同判断。
- 管理员可确认/合并/拆分；用 20 个真实高频系列建立标注集，单列误合并率。
- 最新一期优先使用明确报表期次，其次才是修改时间，并展示依据。
- 收藏、最近访问、保存筛选与系列版本时间线；权限改变后立即重新裁剪。
- 出口：标注集达到双方确认阈值，用户任务实测改善，原始文件仍可追溯。

## 第四批：可持续治理

- 目录负责人、敏感级别、保留期、更新周期；无负责人清单与季度复核。
- 扫描任务持久化；增量/指定目录/完整校准、取消、失败重试与幂等状态。取消/部分失败不能删除疑似失效记录。
- 归档周期与例外：节假日、本期无数据、豁免到期、证据关联、关闭/撤回审计。
- 下载策略和多级审批在敏感级别与 ACL 稳定后实现。只读演算验证策略，不预设自动放行。
- 外部通知在明确飞书/企业微信/邮件渠道、收件人、凭据与静默策略后接入；本次不向任何人发送通知。

## 第五批：订阅、搜索运营与 AI

- 订阅与摘要依赖可靠系列和通知投递；通知合并、去重、限频、静默与失败重试先于放量。
- 查询词运营先建立受控、可删除的收集策略，再展示热门词和零结果词。
- AI 首先只查找、解释来源和新鲜度；不得绕过权限或回答无引用数字。外部机器人作为独立集成验收。

## 发布与回滚

每批独立提交可审查代码与测试结果，数据库新增表向后兼容。迁移前保留索引备份，不改动网盘源文件。与已有功能冲突时保留原功能入口。外部集成、业务 ACL 范围、通知接收人和真实试点目标由业务确认；这些信息不阻塞第一批本地工程改造。

## 补充交付：悬浮助手与应用目录权限

2026-11-04 补齐中断的两项要求：

- AI 改为右下角悬浮机器人，点击展开非模态聊天窗；支持快捷提问、Enter 发送、Shift+Enter 换行、Esc 收起、⌘/Ctrl+J、保留本页对话和手机布局。不再全屏遮挡或持久化旧抽屉宽度。
- 默认开启 `DIRECTORY_ACL_ENABLED=true`。即使开发配置 `AUTH_REQUIRED=false`，目录权限开启时 API 仍强制登录；预览密钥、审批票据不能绕过目录权限。
- 超级管理员在「人员权限 → 目录访问授权」按成员或精确部门分配目录。允许向子目录继承；拒绝优先；只授权深层目录时可见必要祖先，但不显示兄弟文件。部门管理员不会自动获得全盘权限，也不能改账号角色、重置超管密码或授权目录。
- `directory_access.py` 使用请求上下文策略及连接局部 SQLite 视图，读取在召回/聚合/分页前按权限过滤。覆盖搜索、AI 候选及目录上下文、统计、组织树、文件/预览字节、分析/导出、保存方案、归档与下载审批。组织树缓存包含账号及授权指纹；撤权后的新请求立即重验。
- 授权保存、覆盖和撤销写入审计表；普通账号默认无文件访问权。本次未给现有成员猜测或新增真实授权，源目录和模拟文件名称保持原状。

验证：56 项后端回归通过；前端脚本语法检查通过。浏览器验证了桌面与手机聊天窗、提问、未授权提示及授权表单加载。隔离数据库测试覆盖了授权保存/撤销、继承、拒绝、兄弟前缀/特殊字符、召回前过滤、缓存隔离、越权读取和正常管理操作。测试服务的 UI 授权提交被自动审批拦截，未更改该成员的权限；写入与撤销通过独立临时数据库测试验证。

边界：这是应用目录 ACL，不会改操作系统或网盘权限；当前预览仍会向已获目录访问权的用户返回原表字节，不构成只读脱敏或禁止原件导出的安全边界。NAS 权限同步和服务端限行预览仍按第二批推进。

性能补充：以当前 130,452 份索引实测，移除逐行 Python 权限回调，并新增覆盖索引及本地月份边界聚合后，管理员仪表盘统计约 0.5 秒，指定目录权限视角约 2 秒（本机单次调用，非生产并发承诺）。月度图按本地日历最近 12 个月统计，包含零值月份。预览缓存键增加数据库/根目录/来源路径指纹及纳秒修改时间，防止跨来源或同秒更新时复用错误字节。
