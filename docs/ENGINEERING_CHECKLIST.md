# 工程化验收清单

本文定义这个内网文件检索与轻量 BI MVP 在试点和生产推广前必须通过的检查。代码测试通过只说明示例链路正常，不代表已经验证真实共享盘性能或完成生产安全验收。

## 1. 系统不变量

1. **普通搜索只访问本地索引。** `/api/search` 不应调用目录扫描、`stat()`、打开 Excel 或遍历 SMB 目录；只有后台建索引和用户主动分析某个文件时才访问原始共享盘。
2. **索引记录不是文件权限。** 文件打开和 BI 分析前必须重新确认路径位于当前授权根目录内；上线时还需要把用户身份与真实文件 ACL 接起来。
3. **索引清理必须 fail-safe。** 只有一次扫描完整遍历目录、没有权限或 I/O 异常时，才能删除未见到的旧记录。部分扫描只报告异常，不能将旧索引误判成已删除文件。
4. **数据计算不能静默丢数。** 无效工作表、坏 CSV 行、不能转成数值的非空指标值必须明确报错，不得自动切换工作表或悄悄跳过记录。
5. **分析不改原件。** BI 读取原工作簿，导出写入新的结果文件；大文件必须受单文件字节数和分析行数限制。
6. **模型不是检索依赖。** AI 未配置、超时或返回不合法内容时，本地检索仍可完成；AI 只能重写查询或对已有索引候选排序，不能编造文件路径。

## 2. 变更门禁

涉及索引表结构、FTS、扫描清理、路径解析、筛选或聚合逻辑时，至少执行：

```bash
python -m compileall -q fast_file_finder
pytest -q fast_file_finder/tests
```

修改前端 JavaScript 后，应至少执行浏览器实际操作回归；当前 CI 会检查 Python 编译与后端测试，但不能替代浏览器兼容性验证。

## 3. 内测前检查

- [ ] 从 `.env.example` 创建 `.env`，确认 `FILE_ROOT` 指向服务账号真实有权限访问的目录。
- [ ] 索引数据库位于服务机器本地磁盘，不放回待检索的慢速共享盘。
- [ ] 先选一个授权业务子目录，不要一上来扫描整个网盘根目录。
- [ ] 检查索引状态中的扫描异常数；若是部分完成，先排除权限/IO 问题后再重试。
- [ ] 用业务人员真实常用的文件名、简称、月份、部门词建立搜索验收集，记录 Top 5/Top 10 命中率和搜索延迟。
- [ ] 至少抽查 10 份真实 Excel，覆盖多工作表、空值、重复表头、日期、数值文本、公式、超大文件和损坏文件。
- [ ] 将 BI 交叉表结果与人工 Excel 透视结果逐项对账，尤其确认空值、筛选、聚合和行数截断提示。
- [ ] 仅在确需其他电脑访问时绑定 `0.0.0.0`，并配置非空 `APP_ACCESS_TOKEN`；不要把真实令牌提交到 Git。

## 4. 推荐试点指标

这些是建议的验收目标，必须用公司真实数据测量后才能决定是否达标，不是当前环境的性能承诺。

| 指标 | 建议验收方法 |
| --- | --- |
| 本地检索延迟 | 预热后连续执行至少 200 次查询，记录 P50/P95/P99；初期目标可设 P95 ≤ 500 ms |
| 搜索准确率 | 建立不少于 50 条真实查询及人工标注结果，统计 Top 5 命中率和零结果率 |
| 首次索引 | 记录文件数、总耗时、每秒处理文件数、异常数与数据库大小 |
| 增量索引 | 新增、修改、删除各准备测试文件，确认下一次完整扫描后索引一致 |
| 失败安全性 | 模拟无权限目录和 I/O 异常，确认索引标记为“部分完成”且不清理旧记录 |
| BI 正确性 | 将多个筛选/聚合/交叉表组合与 Excel 结果比对；行数超限时必须保留明显警告 |

## 5. 生产上线前的 P0 项

- **企业身份认证：** 当前可选共享令牌仅提供基础入口保护，不支持区分具体员工身份。
- **逐用户文件 ACL：** 必须确认用户只能搜索、预览和分析自己有权访问的文件，不能因为服务账号对共享盘有广泛权限而扩大访问范围。
- **审计与告警：** 增加登录、索引任务开始/结束、扫描异常、导出与拒绝访问的审计记录；避免写入访问令牌和不必要的敏感搜索词。
- **备份与恢复：** 明确索引库备份、损坏后的重建、索引版本迁移和回滚流程。元数据可重建，但保存的分析方案需要有保留策略。
- **终端打开链路：** 在指定的 Windows、Edge/Chrome、Office 版本和 SMB 权限策略下，验证点击后能否打开原文件、是否可保存回写。
- **容量与并发压测：** 用实际文件数量、目录深度、文件大小分布与并发用户规模压测；不要依据小样本耗时决定 SSD 迁移或采购硬件。

## 6. 已知限制

- 文件内容未建立全文索引；第一阶段只按文件元数据查找。
- 单次 BI 分析有行数及文件大小上限。达到限制时是截断分析，不是对整个工作簿的精确全量结果。
- 宏、复杂公式、合并表头、多层标题、跨工作表关联和非结构化报表不保证自动转成标准明细表。
- `APP_ACCESS_TOKEN` 是所有用户共用的门槛，不能替代企业 SSO、逐用户授权、HTTPS 和受控反向代理。
