# 飞书登录、同步日报与新增清单

## 配置

1. 在飞书开放平台创建并发布企业自建应用，设置可用范围。启用机器人。选择群发时，把机器人加入指定内部群。
2. 将 `FEISHU_APP_ID`、`FEISHU_APP_SECRET` 放入服务环境。将完整 HTTPS 回调地址 `https://你的域名/integrations/feishu/callback` 同时写入 `FEISHU_REDIRECT_URI` 和飞书后台的重定向 URL 白名单。应用需能读取登录用户身份及授权范围内的部门和人员。
3. 在飞书应用的「权限管理 → 数据权限」配置指定测试成员或部门，发布版本。平台先检查能否读取根部门，受限时按飞书授权名单同步。成员姓名字段不可见时，列表以成员标识末尾区分。超级管理员在平台「成员管理」点击「同步飞书」。飞书登录使用匹配到的平台账号的系统角色与目录授权。登录页同时提供飞书和账号密码入口。
4. 在受限共享的多维表格建一张「每日新增文件」数据表，添加六个**文本**字段。主字段可用「文件名」，其余为「日期」「文件格式」「相对目录」「首次入库时间」「条目标识」。让应用具备数据表编辑权限，并在开放平台开通写入记录权限。
5. 在「推送任务」新建日报，选择一位有权了解数据源统计的飞书成员或一个工作群，再设置发送时间。若启用新增文件多维表，填写应用和表格标识，并可用 `FEISHU_DAILY_BTABLE_URL` 添加新增清单按钮。
6. 使用环境配置的旧版实例会沿用 `FEISHU_DAILY_ENABLED`、`FEISHU_DAILY_TIME` 及原先的个人或群目标作为原任务。后台可直接新增、调整或删除任务。容器使用仓库根目录的 `.env`，裸跑 Python 时通过服务环境传入，或填写 `fast_file_finder/.env`。

## 管理日报推送任务

超级管理员可以在「推送任务」新建多条日报。每条任务分别选择名称、北京时间、启停状态和一位飞书成员或一个群。例如，09:00 私发给负责人，18:00 发到运营群。各任务使用相同的日报格式，同日归档监控明细取首次推送时的检测快照。编辑、暂停或删除只作用于选中的任务。旧版已配置的接收人和当日发送记录沿用为原任务。

发送到群时，先在飞书目标群打开「设置 → 群机器人 → 添加机器人」，选择本应用机器人，并确认它在群内可以发言。从群设置复制群 ID 后，可以在任务编辑页检查机器人是否在群内。该检查只读取成员状态，不发送卡片。[飞书发送消息说明](https://open.feishu.cn/document/uAjLw4CM/ukTMukTMukTM/reference/im-v1/message/create)

## 统计与归档

- 新增按文件首次写入当前索引的北京时间归档。普通内容更新、重复扫描与同日同一路径重新入索引均不重复计数。新数据源首次全盘扫描用于建立基线，存量文件不进入日报。启用前的历史索引不回填。
- 日预警卡片展示发送时的扫描进度、当日修改文件数、新入索引数和其中的表格数。归档检测按规则统计逾期和无法核验，技术执行失败单独提示。休息日暂停和未到首次检测节点不算异常。
- 当天的文件在同一张多维表里逐批追加，按「日期」分组即可回看。发送日报之后，新入库文件继续落表。清单发送文件名、格式、相对目录与入库时间等索引信息，文件原件、文件内容和服务器绝对路径不随清单发送。用飞书自身的共享设置控制清单可见范围。
- 任务约每分钟检查一次。写表失败保留待写入记录并重试。日报当天到点推送，异常时在飞书消息幂等窗口内重试。管理员可在「推送任务」查看发送、待写入和失败状态。部署多个实例时，应让一个实例负责日报发布。

## 云服务器演示

本机和云服各用自己的回调地址，可以同时配置到飞书应用的重定向 URL 白名单。本机可使用 `http://127.0.0.1:8093/integrations/feishu/callback`。公网演示使用绑定了证书的 HTTPS 入口，并将该入口的完整 `/integrations/feishu/callback` 地址同时填入飞书白名单和云端 `FEISHU_REDIRECT_URI`。授权前从同一个 HTTPS 入口打开平台，浏览器才能在回调时带回登录状态。

使用 `docker-compose.cloud.yml` 时，在云服项目自己的 `.env` 配置应用凭据与回调，并重建服务。云端的本地账号在云服页面同步与绑定。要演示日报时，再配置专用飞书群和多维表，以及发送与写表权限。

## 真实成员与目录权限

- 飞书应用读取成员的手机号、部门和职务。手机号字段使用「获取用户手机号」（`contact:user.phone:readonly`），部门和职务缺字段时分别检查「获取用户组织架构信息」（`contact:user.department:readonly`）和「获取用户受雇信息」（`contact:user.employee:readonly`）。数据授权范围应包含要管理的成员与部门。姓名字段缺失时可检查「获取用户基本信息」（`contact:user.base:readonly`）。发布版本后重新同步。
- 在「成员管理」维护平台账号的真实手机号，也可以编辑自定义部门与岗位。同步只关联手机号唯一且账号启用的已有普通账号。管理员手机号匹配后需要由超级管理员确认。新成员先创建平台账号再同步。
- 已同步的飞书部门及「飞书部门 · 岗位」可作为文件授权对象。飞书子部门继承可访问的上级部门授权，文件子目录继承父目录授权。明确拒绝优先，下载权限仍支持审批。查看成员最终权限时可以追到具体授权来源。飞书只提供职务名称时，岗位授权使用部门和完整职务名，职务更名后需核对原规则。
- 同步后会重新评估调岗、转部门和移出授权范围的成员。旧登录会话在身份关联失效时会被撤销。普通人员仍可使用已配置的本地登录方式；自定义部门和个人授权按本地规则生效。
- 手机号比对在服务端完成。飞书成员列表仅显示手机号尾号。演示模式下，升级前已确认的临时登录关联还可用于演示，待手机号验证后才参与飞书部门和岗位授权；正式环境要求手机号匹配。

成员名单合并展示飞书和平台账号，可按账号来源、姓名和部门筛选。已关联成员按飞书资料显示。飞书返回的根组织成员会标为「根组织」。成员行内可维护平台角色、登录凭据和自定义部门。同步名录可以看到待开通的成员，账号创建仍由管理员明确操作。

飞书应用可以获得某位根组织成员的授权，而整个根组织仍超出应用的数据范围。这时人员页会标明按指定成员或部门同步。要纳入更多同事，在飞书「权限管理 → 数据权限」将他们或对应部门加入通讯录范围，确认版本生效后重新同步。

已关联且有效的账号优先显示飞书姓名。个人资料中的组织信息取自飞书通讯录。平台角色、自定义部门和授权规则继续按平台账号管理。演示模式下此前确认的临时关联也会显示飞书姓名，并在通讯录标明核验状态。

## 日预警明细

「归档合规 → 日报明细」按北京时间保存每个启用监控规则的日报数据。每条记录有报表名、检测日期、更新数量、状态、最近更新、截止时间、责任人和异常原因。更新数量统计同一监控规则下当天修改的文件。日规则未到截止且尚无有效更新时，标为待检测。

系统提供全部、正常、异常和待检测筛选，并可下载所选日期的异常 CSV。日报发布开始时固定该日的一份检测快照，卡片、系统和多维表从这份快照读取。系统登录和文件目录授权仍适用于查看和下载。

飞书卡片的三个入口分别是查看系统明细、打开报表明细多维表、下载异常清单。使用 `FEISHU_REPORT_BTABLE_APP_TOKEN`、`FEISHU_REPORT_BTABLE_TABLE_ID` 和 `FEISHU_REPORT_BTABLE_URL` 配置专门的报表状态多维表。多维表「状态」是单选字段，可筛选正常、异常和待检测。原有新增文件清单仍使用 `FEISHU_DAILY_BTABLE_*` 变量。应用需要目标多维表的编辑权限。日常写入使用「新增记录」权限。需要由应用创建数据表及「正常」「异常」两个筛选视图时，额外开通应用身份的「查看、评论、编辑和管理多维表格」（`bitable:app`）。

`FEISHU_DAILY_SYSTEM_URL` 可显式设置系统访问入口，未设置时使用飞书登录回调所在的系统地址。本机演示卡片的系统和下载按钮适用于运行服务的同一台电脑。云端展示可设置访问同一数据源的云端地址。
