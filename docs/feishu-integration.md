# 飞书登录、同步日报与新增清单

## 配置

1. 在飞书开放平台创建并发布企业自建应用，设置可用范围。启用机器人并加入指定内部群。
2. 将 `FEISHU_APP_ID`、`FEISHU_APP_SECRET` 放入服务环境。将完整 HTTPS 回调地址 `https://你的域名/integrations/feishu/callback` 同时写入 `FEISHU_REDIRECT_URI` 和飞书后台的重定向 URL 白名单。应用需能读取登录用户身份及授权范围内的部门和人员。
3. 在飞书应用的「权限管理 → 数据权限」配置指定测试成员或部门，发布版本。平台先检查能否读取根部门，受限时按飞书授权名单同步。成员姓名字段不可见时，列表以成员标识末尾区分。超级管理员在平台「人员权限 → 飞书企业应用」点击「同步并匹配」。飞书登录使用匹配到的平台账号的系统角色与目录授权。
4. 在受限共享的多维表格建一张「每日新增文件」数据表，添加六个**文本**字段。主字段可用「文件名」，其余为「日期」「文件格式」「相对目录」「首次入库时间」「条目标识」。让应用具备数据表编辑权限，并在开放平台开通写入记录权限。
5. 配置 `FEISHU_DAILY_CHAT_ID`（接收群的 `oc_...` 标识）、`FEISHU_DAILY_BTABLE_APP_TOKEN` 和 `FEISHU_DAILY_BTABLE_TABLE_ID`。若填写 `FEISHU_DAILY_BTABLE_URL`，日报会附上这个飞书链接。提醒只发到指定群，群内应只包含有权了解数据源全局统计的成员。
6. 设置 `FEISHU_DAILY_ENABLED=true`，重启服务。`FEISHU_DAILY_TIME` 缺省为北京时间 18:00。可以只配置群或只配置数据表。容器使用仓库根目录的 `.env`，裸跑 Python 时通过服务环境传入，或填写 `fast_file_finder/.env`。

## 统计与归档

- 新增按文件首次写入当前索引的北京时间归档。普通内容更新、重复扫描与同日同一路径重新入索引均不重复计数。新数据源首次全盘扫描用于建立基线，存量文件不进入日报。启用前的历史索引不回填。
- 日报展示发送时的扫描进度、今日新增文件数和其中的表格数。归档检测按规则统计逾期和无法核验，技术执行失败单独提示。休息日暂停和未到首次检测节点不算异常。
- 当天的文件在同一张多维表里逐批追加，按「日期」分组即可回看。发送日报之后，新入库文件继续落表。清单发送文件名、格式、相对目录与入库时间等索引信息，文件原件、文件内容和服务器绝对路径不随清单发送。用飞书自身的共享设置控制清单可见范围。
- 任务约每分钟检查一次。写表失败保留待写入记录并重试。日报当天到点推送，异常时在飞书消息幂等窗口内重试。管理员可在人员权限页查看发送、待写入和失败状态。部署多个实例时，应让一个实例负责日报发布。

## 云服务器演示

本机和云服各用自己的回调地址，可以同时配置到飞书应用的重定向 URL 白名单。本机可使用 `http://127.0.0.1:8093/integrations/feishu/callback`。公网演示使用绑定了证书的 HTTPS 入口，并将该入口的完整 `/integrations/feishu/callback` 地址同时填入飞书白名单和云端 `FEISHU_REDIRECT_URI`。授权前从同一个 HTTPS 入口打开平台，浏览器才能在回调时带回登录状态。

使用 `docker-compose.cloud.yml` 时，在云服项目自己的 `.env` 配置应用凭据与回调，并重建服务。云端的本地账号在云服页面同步与绑定。要演示日报时，再配置专用飞书群和多维表，以及发送与写表权限。

## 真实成员与目录权限

- 飞书应用读取成员的手机号、部门和职务。手机号字段使用「获取用户手机号」（`contact:user.phone:readonly`），部门和职务缺字段时分别检查「获取用户组织架构信息」（`contact:user.department:readonly`）和「获取用户受雇信息」（`contact:user.employee:readonly`）。数据授权范围应包含要管理的成员与部门。姓名字段缺失时可检查「获取用户基本信息」（`contact:user.base:readonly`）。发布版本后重新同步。
- 在「成员与访问权限」维护平台账号的真实手机号，也可以编辑自定义部门与岗位。同步只关联手机号唯一且账号启用的已有普通账号。管理员手机号匹配后需要由超级管理员确认。新成员先创建平台账号再同步。
- 已同步的飞书部门及「飞书部门 · 岗位」可作为文件授权对象。飞书子部门继承可访问的上级部门授权，文件子目录继承父目录授权。明确拒绝优先，下载权限仍支持审批。查看成员最终权限时可以追到具体授权来源。飞书只提供职务名称时，岗位授权使用部门和完整职务名，职务更名后需核对原规则。
- 同步后会重新评估调岗、转部门和移出授权范围的成员。旧登录会话在身份关联失效时会被撤销。普通人员仍可使用已配置的本地登录方式；自定义部门和个人授权按本地规则生效。
- 手机号比对在服务端完成。飞书成员列表仅显示手机号尾号。演示模式下，升级前已确认的临时登录关联还可用于演示，待手机号验证后才参与飞书部门和岗位授权；正式环境要求手机号匹配。
