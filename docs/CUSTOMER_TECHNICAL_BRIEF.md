# 企业文件资产智能检索中心｜客户技术说明（基于现有实现）

> 技术核对版本：2026-11-05，源仓库 `qishen123456/wenjiansuoyin`。本文只说明代码与测试支持的能力；不把演示数据、模拟盘基准或计划项写成生产验收结果。配套 16 页可交互 HTML 演示见 [customer_technology_manual.html](./customer_technology_manual.html)。

## 一、为什么不是“给共享盘加一个 AI 搜索框”

原始企业共享盘往往包含深层业务目录、大量 Excel/CSV 文件、重复命名以及跨部门权限。直接每次在 SMB/NAS 上递归查找会产生高目录 I/O；让模型遍历全部文件名则既慢、成本高，也可能造成敏感元数据外发。

本系统将**发现、召回、解释、查看和取走原件**五种动作拆开：

```text
[企业 NAS / SMB 共享盘，建议只读挂载]
                  │  后台按需/定时扫描文件元数据，不读表格正文
                  ▼
       [动态目录队列 + 有界结果队列]
                  │ 多扫描线程 / 单 SQLite 消费者
                  ▼
        [本地 SQLite 索引 + FTS5]
                  │ 基础数据：文件名、相对路径、类型、大小、mtime/ctime、根目录作用域
                  ▼
       [登录会话 + 应用目录 ACL 过滤]
                  │ 未授权文件先过滤，之后再做 FTS / 统计 / 分页
             ┌────┴────────────┐
             ▼                 ▼
         [普通检索]        [AI 找表助手]
             │                 │ 先读授权索引，模型只做有限候选辅助
             └────┬────────────┘
                  ▼
          [授权文件详情 / 目录导航]
              ┌───┴───────────────┐
              ▼                   ▼
     [JSON 限行预览]          [原件下载申请]
     有限行列、文件上限       管理员审核、限时票据
              └─────────┬─────────┘
                        ▼
                [请求级权限重新校验]
```

普通搜索不打开工作簿，不扫描共享盘，也不依赖模型服务成功；原件仍在原共享盘上，不由扫描任务重写或搬迁。

**源代码：** `fast_file_finder/app.py`、`scan_pipeline.py`、`directory_access.py`、`limited_preview.py`。

## 二、扫描提速：从固定耗时遍历变成可控流水线

### 2.1 动态目录调度

`scan_pipeline.walk_metadata()` 不先切分静态目录区块，而是把待发现子目录追加到共享任务队列。多个线程从队列取任务，深层目录和大目录的负载自然重新分配。

- 线程数默认随 CPU 核数选择 2–8；可通过 `SCAN_WORKERS` 覆盖，代码限制最多 16。
- 使用 `os.scandir()` 和文件 `stat` 读取元数据，而不是打开 Excel 工作簿。
- 跳过符号链接、junction、临时文件及配置排除目录，避免目录越界和无谓扫描。
- 目录任务用完成计数收敛，不把“瞬时队列为空”当成扫描结束。

### 2.2 生产/写库隔离

扫描线程只负责取得元数据并发给有界队列（默认 `SCAN_QUEUE_SIZE=1024`）；单一数据库消费侧处理 SQLite 写入。扫描启动时将已有元数据预读到内存，按照路径、大小、时间判断是否新增、修改或不变。**不变文件不执行逐条数据库更新**。

SQLite 默认每处理 300 条或每 1 秒提交一次；等待读取时也按时间提交，避免 SQLite 写事务被网络 I/O 长时间拖住。这是吞吐与额外内存占用的权衡，不是完全不扫旧目录。

### 2.3 扫描失败安全

一次扫描如果发生目录无权访问、I/O 异常或文件元数据异常，会标识为 `partial`，**不会将扫描期间没看到的旧文件直接删除**。只有完整遍历成功才批量清理本次未见的旧索引；扫描结果含已发现、排除、成功处理、异常及增删改等对账信息，可供管理页查看。

### 2.4 本地基准（不可直接外推至客户 NAS）

| 口径 | 改造前 | 改造后 |
|---|---:|---:|
| 目录规模 | 119,668 个本地模拟文件 | 同目录，同数据 |
| 无变化扫描耗时 | 11.685 秒 | 6.239 秒（4 线程） |
| 进程峰值 RSS | 119,242,752 B | 252,051,456 B |
| 扫描结果 | 完成、0 错误 | 完成、0 错误 |

同机单轮对比耗时减少约 **47%**，但受文件缓存和测试先后顺序影响，且内存成本提高。该性能数据仅代表仓库文档在 2026-11-05 记录的**本地模拟盘实验**；不等于真实 NAS、CIFS、云主机或多人并发场景的保证。技术依据：`docs/SCAN_AND_LIMITED_PREVIEW.md`。

## 三、检索为什么能快

**两阶段工作：**后台建元数据索引；前台执行索引查询。`/api/search` 在 SQLite 的 `file_fts` / `files` 上召回候选，不向共享盘逐一读取文件。

- 中文用字符片段和拼写/业务简称映射辅助；支持英文缩写、关键词、路径、格式、日期与大小等组合。
- 评分引擎综合文件名精确匹配、文件名包含、业务实体匹配、目录命中、文件非空和 FTS 排名；可进一步按修改时间等字段排序。
- 严格模式无结果时可放宽部分关键词，再根据场景扩展到目录匹配。
- 当前索引**没有跨工作簿单元格的全文索引**；“搜 Excel 内文”不能与“搜文件名/目录”混同。
- `mtime` 是源文件最后修改时间，不代表业务报表期次、入库时间或准确的首次创建日期。

## 四、AI 找表的技术执行链

`POST /api/ai/chat` 接收业务自然语言，先通过 `extract_business_keywords` 剔除口语词、抽取业务实体，再向用户**已授权范围内的索引**调用 `candidate_search`。

1. **直接命中：**有较高相关度的真实文件时，返回文件名、所在目录和实际索引证据，无需让模型遍历全盘。
2. **时间问题：**“今天”“昨天”“近 7 天”“最新”等优先由 `answer_dated_file_request` 在授权索引里按 `mtime` 确定性检索，模型只能补充解释，不能伪造文件/时间/数量。
3. **候选不足：**可取有限数量的已授权目录元数据，请配置的模型推测可能的目录和替代搜索词；建议属于“推测”，不等同于文件存在。
4. **模型可选：**可在环境变量中配置主模型与备用模型；失败时保持本地索引检索可用。`ai_expand_query` 与 `ai_rerank` 等函数也支持有限候选的查询改写和语义重排，不能据此宣称每次普通搜索都调用模型。

**隐私边界：**外部模型可能接触用户提问、授权范围内的文件名和目录元数据；默认不上传 Excel 全文。是否允许元数据出网，须由客户数据安全负责人确认。对于模型提示的未知位置，业务方需核对源文件。

## 五、服务端限行预览：不是前端隐藏行

现有 `GET /api/file/{id}/preview-data` 先由后端校验身份和目录权限，然后按请求读取文件，返回 JSON 行列。旧的“完整工作簿字节下发给浏览器再限制显示”原件预览接口和客户端 Worker 已移除。

| 控制项 | 当前实施 |
|---|---|
| 默认 / 最大单页 | 100 行 / 最多 200 行 |
| 最多预览范围 | 前 10,000 行、100 列、50 个工作表 |
| 单元格长度 | 最多 2,000 字符 |
| 默认源文件上限 | 32 MB；旧格式如 xls/xlsb/ods 16 MB |
| 压缩文件展开上限 | 128 MB |
| 并发 | 单应用进程只允许一个未缓存解析任务；繁忙返回 429 |
| 热缓存 | 60 秒，最多 32 页或 16 MB |
| 一致性 | 源文件解析中发生修改返回 409 |
| 复核 | 每次请求按当前会话重新确认授权；缓存响应 `no-store` |

xlsx/xlsm 通过 `openpyxl` 只读解析并显示工作簿**已保存的公式结果**，不会执行公式；CSV/TSV 通过逐行读取处理。它是**有限数据网格预览**，不承诺还原 Excel 原始格式、图表、复杂合并单元格。

**必须向客户明确：**限行 ≠ 字段脱敏 ≠ 防复制/截图。若要隐藏身份证号、报价或薪酬等字段，需要另行定义列级脱敏与可见性策略。

## 六、目录权限与下载审批：两道不同的门

### 6.1 应用目录 ACL（已经实现）

- 超级管理员可以按**用户**或**精确部门**分配目录允许 / 拒绝规则；普通成员默认没有文件可见范围。
- 授权允许继承到子目录，显式拒绝优先；仅授权深层目录时，组织树只保留必要祖先路径，不展示兄弟目录文件。
- 中间件依据当前用户/根目录加载请求策略；`directory_access.ScopedConnection` 的可见视图在 SQL 读取阶段执行筛选，避免未经授权的文件先进入候选再被客户端隐藏。
- 搜索、目录树、首页统计、AI 候选、预览、BI 数据及下载相关查询共用当前授权上下文；授权调整后新请求重验，授权与撤销动作写入审计表。
- `DIRECTORY_ACL_ENABLED=true` 时，即使开发环境另行放宽认证，API 仍要求登录。普通用户不得因为文件 ID 已知而绕开可见范围。

### 6.2 目录可见 ≠ 原件自由下载

普通成员提交下载申请并说明用途，由管理员批准后获取有限期票据；`/api/file/{id}/download` 还会验证当前目录权限及票据。具有相应角色的管理员可按当前内置规则直接下载已授权文件。业务方可在审批页查看申请与处理动作。

### 6.3 仍需对接的生产安全项

本次核对确认的应用 ACL **不是** NAS/SMB 文件系统 ACL：服务运行账号的真实共享盘权限、企业 SSO/AD/LDAP 映射、反向代理 TLS 和认证治理仍需要在现场验收。当前成员密码新增与重置代码仍存在**明文存储**逻辑，必须在正式全员使用前改为安全哈希并处理历史数据。不得向客户描述为已完成全套企业级零信任体系。

## 七、部署方式及已知限制

代码包含 FastAPI 服务、SQLite 元数据索引、Docker 多阶段镜像、开发与生产 Compose 示例。推荐共享盘在宿主机以只读方式挂载，应用以非 root 运行；索引文件放在本地磁盘，不放回慢速网盘；密钥通过运行环境注入而不是写死到源码。

当前 `_scan_lock`、扫描状态等是进程内对象，推荐**单应用进程**避免不同 worker 重复触发扫描。一套服务维护一个 `FILE_ROOT` 根目录；切换根目录后需要重新扫描并区分索引范围。现场公网/跨电脑访问时，服务端“打开文件”不等于用户电脑能直接启动 Office，应使用浏览器预览或受网盘策略约束的共享路径。

## 八、面向客户的验收建议

| 场景 | 证明材料与合格判断 |
|---|---|
| 首次 / 重复扫描 | 真实目录文件总数、扫描时间、异常分类、对账一致，部分扫描不误删 |
| 检索结果正确 | 基于客户常用 50 条业务词人工标注 Top 5 / Top 10，P50/P95/P99 |
| AI 找表 | 同一提问确认返回来源文件，未命中给建议不编造，模型失败仍可搜索 |
| 预览 | 大文件、空文件、公式、页码/行列上限、并发 429、文件变化 409 |
| 权限 | 用户/部门继承、拒绝优先、跨目录文件 ID、撤权后缓存命中、无授权零结果 |
| 下载审批 | 普通员工未经批准不能取原件、票据有效期、审批记录与再次授权 |
| 部署运维 | 真实 NAS 挂载、只读测试、备份恢复、审计、TLS/SSO 与密码哈希迁移 |

自动化测试入口：`python -m compileall -q fast_file_finder` 和 `pytest -q fast_file_finder/tests`；覆盖示例见 `tests/test_scan_and_preview_upgrade.py`、`tests/test_directory_access.py`。测试通过不能替代真实服务器与共享盘验收。
