# 企业文件检索与轻量 BI 分析中心

这是一个面向内网共享盘的可运行 MVP。开发顺序是：**先建立文件元数据索引并验证检索速度，再让员工选择单个表格进行轻量 BI 分析；AI 只是可选的检索兜底，不是系统运行的前提。**

> 当前版本可在本地/内网启动，检索、工作簿读取、字段识别、筛选、聚合、交叉表、图表、保存分析方案和 Excel 导出已实现并做过接口冒烟测试。尚未连接你公司的真实共享盘，也未完成公司级单点登录、逐用户 ACL 权限过滤、审计和终端一键启动 Excel 验证，因此它是内测 MVP，不是可以直接面向全员开放的生产系统。

## 一、系统结构

```text
浏览器
  ├── 文件检索页
  │    └── FastAPI → SQLite FTS5 文件索引 → 文件名/目录匹配与排序
  │                            └── 可选 AI：只扩展关键词或重排少量索引候选
  └── 轻量 BI 工作区
       └── 通过索引中的 file_id 找到单个原文件
            └── pandas 按需读取工作表 → 筛选 → 聚合 → 交叉表
                 ├── 浏览器内 SVG 图表
                 ├── 数据预览/字段信息
                 └── 导出新 Excel（汇总表 + 筛选明细 + 分析说明）
```

原始文件不搬迁、不修改。SQLite 元数据索引建议放在运行服务机器的本地 SSD。普通检索只读索引库，不会每次搜索都扫描共享盘；建立/更新索引时才会在后台遍历目录元数据。BI 只读取用户主动选择的单个工作簿。

升级到带有根目录作用域的 v0.3 后，旧数据库中的历史记录会先隐藏在当前搜索结果之外，执行一次“建立 / 更新索引”后会重新归属当前 `FILE_ROOT`。如果升级后索引数量暂时显示为 0，这是为了避免共享目录变更时把旧路径错误地展示出来。

## 本轮工程化加固（v0.3）

- SQLite 连接统一通过上下文管理器关闭，异常时回滚；WAL 模式只在启动初始化时设置，避免每个请求重复修改数据库级设置。
- 索引记录增加根目录作用域和扫描代次标记。搜索只返回当前配置目录的数据；扫描清理按 ID 分批执行，不再在内存保存全量路径集合。目录扫描存在权限/IO 异常时，不清理旧索引。
- 索引状态读写加锁，日志记录扫描开始/结束、异常类别和搜索耗时，不记录原始搜索词或访问令牌，方便后续做性能基线。
- BI 交叉表每个指标只聚合一次，避免在组装单元格和图表时重复执行相同的透视运算。
- 并发启动索引任务使用线程锁在入口处抢占，避免重复请求都返回“启动成功”；扫描状态采用锁保护快照。扫描有权限/IO 错误时单独标记为“部分完成”，不显示成全量成功。
- 默认跳过文件符号链接，避免把授权根目录之外的目标意外纳入索引。
- 传入不存在的工作表名会返回明确错误，不再静默切换到第一张表；CSV 结构异常不再静默跳过坏行，防止分析结果看似正常但实际丢数。
- 对筛选条件数量、字段长度和保存方案 JSON 大小增加边界校验。
- 可选配置 `APP_ACCESS_TOKEN`，给内网访问增加共享令牌门槛。令牌不配置时不启用；共享令牌不是用户身份认证，也不能替代逐用户文件权限和公司 SSO。服务启动时会对未配置令牌的情况打印警告。

## 二、当前功能

### 文件检索

- 扫描配置目录中的 Excel/CSV 表格，索引文件名、路径、扩展名、大小、修改时间。
- SQLite FTS5 + 中文字符片段召回 + 应用层相关度排序。
- 支持按扩展名过滤、按相关度或修改时间排序、查看最近更新文件。
- 显示匹配原因、路径、修改时间和文件大小；可复制路径或尝试打开共享路径。
- 后台扫描时仍可查询之前已经建立的索引。
- 更新时依据路径、文件大小和修改时间跳过未变化文件；完整扫描成功后清理已经不存在的索引记录。

### AI 兜底（可选）

- 先搜索本地索引。
- 没有候选时，AI 将用户描述改写为少量关键词，再重新查索引。
- 有候选但本地匹配度仍较低时，最多将 30 条候选元数据发送给配置的模型进行重排。
- **不会要求 AI 全量读取所有文件名，也不会将 Excel 单元格内容发给 AI。**
- 默认关闭。启用外部模型前，必须先评估文件名、目录名等元数据是否允许发往该服务。

### 轻量 BI（已实现）

1. **工作簿与工作表**：按已索引文件 ID 打开工作簿，查看和切换工作表。
2. **字段识别**：识别字段名称、数值/日期/文本类型、非空数量、去重数和样例值。
3. **原始预览**：显示前 `PREVIEW_ROWS` 行，帮助确认字段结构；不修改原文件。
4. **交叉表**：支持行维度、列维度、一个或多个统计指标组合。
5. **聚合计算**：求和、计数、平均值、中位数、最小值、最大值、去重计数。
6. **多条件筛选**：包含、等于、不等于、大于、大于等于、小于、小于等于、为空、不为空，多个条件按 AND 组合。
7. **图表**：根据汇总结果生成柱状图、折线图；不依赖公网 CDN。
8. **结果导出**：另存新 Excel，包含“交叉汇总”“筛选后明细”“分析说明”三个工作表，不覆盖原始文件。
9. **保存分析方案**：按文件保存常用工作表、维度、指标、筛选和聚合配置，可再次应用。
10. **大文件保护**：可设置单文件大小上限和单次分析最大行数，避免超大工作簿把服务内存拖垮；超过行数时，界面会显示截断提醒。

## 三、运行环境与安装

建议 Python 3.10 或以上。第一轮可先在能访问共享盘的 Windows 内网机器上运行，也可在已挂载共享目录的 macOS/Linux 机器上验证检索与 BI。**Windows 服务需要具备共享目录访问权限；若使用映射盘符，服务账号可能看不到该映射盘，优先使用 UNC 路径。**

### Windows PowerShell

```powershell
cd fast_file_finder
python -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install -r requirements.txt
Copy-Item .env.example .env
```

编辑 `.env`：

```dotenv
FILE_ROOT=\\172.11.111.11\部门共享\报表
INDEX_DB_PATH=./data/file_index.db
ALLOWED_EXTENSIONS=.xlsx,.xls,.xlsm,.xlsb,.csv,.tsv,.ods
MAX_ANALYSIS_FILE_MB=256
MAX_ANALYSIS_ROWS=200000
PREVIEW_ROWS=100
```

请把 `FILE_ROOT` 改成真实路径。`.env` 中路径要按 dotenv 格式填写；UNC 路径建议复制到 `.env` 后检查反斜杠和共享名是否正确。

本机体验时只监听本机回环地址：

```powershell
uvicorn app:app --host 127.0.0.1 --port 8080
```

要给内网其他员工访问时，先在 `.env` 设置随机长 ASCII 令牌，例如 `APP_ACCESS_TOKEN=替换为随机长令牌`，再启动：

```powershell
uvicorn app:app --host 0.0.0.0 --port 8080
```

启动脚本默认只监听 `127.0.0.1`。确需开放内网访问时，macOS/Linux 用 `APP_HOST=0.0.0.0 ./start_macos_linux.sh`，Windows PowerShell 用 `$env:APP_HOST='0.0.0.0'; .\start_windows.ps1`；脚本会检查 `.env` 是否配置了共享令牌。令牌只是基础入口保护，正式面向全员仍需公司 SSO、逐用户文件权限、审计和反向代理。

也可以运行 `start_windows.ps1` 自动创建虚拟环境、安装依赖并启动服务（前提是已配置好 `.env`，并且当前网络能够访问 Python 包源）。

### macOS / Linux

```bash
cd fast_file_finder
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env
```

如果共享盘已经挂载，例如：

```dotenv
FILE_ROOT=/Volumes/企业网盘/报表
INDEX_DB_PATH=./data/file_index.db
```

启动：

```bash
uvicorn app:app --host 0.0.0.0 --port 8080
```

也可以运行 `./start_macos_linux.sh` 自动安装依赖并启动（首次运行会先创建 `.env`，填写目录后再运行一次）。

本机访问 `http://127.0.0.1:8080`；内网其他电脑访问 `http://运行服务的机器IP:8080`。如其他电脑无法访问，请检查防火墙、监听地址和公司网络策略。内网测试阶段建议先只开放给开发/业务试用小组。

## 四、先用样例验证完整链路（建议）

项目附带 `demo_data/DEMO_供应商结算明细.xlsx`，其中包含“结算明细”“供应商信息”“月度区域汇总”三个工作表，数据为虚构演示数据，不代表公司实际数据。

先把 `.env` 中的根目录临时配置为：

```dotenv
FILE_ROOT=./demo_data
```

启动服务后点击“建立 / 更新索引”，搜索“供应商结算明细”，点击“开始分析”。可以尝试：行维度选“供应商名称”、列维度选“月份”、指标选“结算金额”、聚合方式选“求和”，然后生成交叉表、查看图表并导出 Excel。还可以切换到“区域”字段添加筛选条件。

确认功能熟悉后，再把 `FILE_ROOT` 改为真实共享目录，重启服务并重新建立索引。不要把样例目录误当成真实业务网盘。

## 五、第一轮真实网盘试运行流程

1. 选择一个有代表性的业务目录作为 `FILE_ROOT`，先不要直接扫整个共享根目录。
2. 启动系统，确认右侧显示“索引服务已连接”。
3. 点击“建立 / 更新索引”，观察索引进度、错误数和总耗时。
4. 试搜 10～20 个常见关键词，记录前 10 条结果的命中情况和延迟。
5. 点击某个 Excel 的“开始分析”，确认工作表、字段和预览内容正确。
6. 配置行维度（如供应商）、列维度（如月份）、指标（如金额）、聚合方式（如求和），点击“生成分析结果”。
7. 切换图表，增加筛选条件，再导出 Excel，核对汇总值是否与原文件一致。
8. 若检索快但首次扫描慢，先优化目录范围和扫描方式；只有证明存储访问本身是瓶颈后，才考虑 SSD 迁移。

## 六、BI 使用例子

假设表格列为：`供应商`、`月份`、`区域`、`结算金额`。

- 行维度：`供应商`
- 列维度：`月份`
- 统计指标：`结算金额`
- 聚合方式：`求和 SUM`
- 筛选条件：`区域 等于 华东`

结果会生成按供应商和月份交叉的结算金额表，同时绘制图表。导出的 Excel 会保留该汇总表、应用筛选条件后的明细和本次分析参数说明。

## 七、常见问题

### 搜索很快，但结果太少或不准

检查文件是否已经完成索引、目录是否配置到正确层级、文件扩展名是否包含在 `ALLOWED_EXTENSIONS`。可以尝试更短的关键词。后续再启用 AI 查询改写/候选重排，而不是直接把全盘文件名给模型。

### 首次索引特别慢

这是共享盘目录遍历与 SMB/网盘响应成本，不是单次搜索的性能。先从高价值目录小范围试跑；索引建立后检索不应重复遍历该目录。后续可以针对具体存储协议接入变更通知或低频增量巡检。

### 工作簿读取失败

请查看错误提示。确认当前文件类型在允许列表内、Excel 文件不是损坏文件、服务账号有读取权限、对应依赖安装成功。`.xls`、`.xlsb` 和 `.ods` 使用不同读表引擎。复杂宏、公式缓存、合并表头和非结构化报表不保证能自动整理为可透视明细表。

### 聚合计算显示数据行数上限提醒

当前通过 `MAX_ANALYSIS_ROWS` 控制一次分析最多读取的行数（默认 200,000）。达到上限会按读取到的前 N 行计算，结果可能不是全表结果。正式使用前必须根据典型文件体量调整上限，并在界面明确显示截断状态；不要忽略提醒把部分数据当成全量结论。

### 点击后没有直接启动 Excel

这是浏览器安全边界。现有界面提供复制路径和尝试打开入口，但不能保证在所有浏览器和操作系统上直接启动桌面 Excel。需要根据公司主要终端、Edge 策略、Office 版本及 SMB 路径另行做终端验证，不能通过普通网页脚本任意执行本地程序。

## 八、核心 API

- `GET /api/health`：服务健康检查。
- `GET /api/index/status`：索引数量、大小、扫描状态。
- `POST /api/index/start`：启动后台索引。
- `GET /api/search?q=供应商结算&limit=30`：搜索索引。
- `GET /api/recent?limit=10`：最近修改文件。
- `GET /api/analysis/file/{file_id}?sheet_name=工作表`：读取所选文件的工作表和字段信息。
- `POST /api/analysis/run`：执行筛选、聚合和交叉表计算。
- `POST /api/analysis/export`：导出分析 Excel。
- `GET/POST /api/analysis/saved`：查看、保存分析方案。
- `DELETE /api/analysis/saved/{saved_id}`：删除分析方案。

## 九、正式推广前还必须补齐

- 公司统一登录或 SSO。
- 基于真实文件 ACL 的逐用户权限过滤，不能只依赖“文件根目录限制”。当前内测前必须确认访问系统的人员本身已拥有整个配置目录的授权。
- 审计日志、请求限流、异常告警、备份与索引重建流程。
- 定时增量同步/文件变更通知，减少反复全量扫描。
- 终端真实环境下的一键打开验证。
- 按实际 Excel 复杂度完善数据类型处理、错误提示和超大文件任务状态。
- 在典型生产数据规模上做压测和准确性验收；小样本耗时不能用于承诺全量性能。

## 十、性能验收建议

自动化接口回归测试：

```bash
pip install -r dev-requirements.txt
pytest -q
```

测试覆盖检索命中、工作表切换、交叉表求和、筛选聚合、多指标交叉表、保存方案和 Excel 导出。

至少记录：文件总数、目录数、首轮扫描耗时、更新扫描耗时、索引文件大小、检索 P50/P95、前 10 条命中率、文件打开成功率、BI 单次读取/计算耗时以及导出文件是否与原始数据核对一致。需要用真实网盘和真实典型查询测试后，再决定是否迁移 SSD。
